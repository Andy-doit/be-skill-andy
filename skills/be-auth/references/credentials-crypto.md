# Credentials, Password Hashing & Cryptography

## 1. When to read this
Read this when hashing passwords, comparing API keys, secrets, or tokens, implementing MFA validation, or configuring encryption keys.

---

## 2. Decision table

| Question | Smallest mechanism that holds the invariant | Take more complex mechanism only when |
|---|---|---|
| How to compare incoming API keys or token signatures? | `crypto.timingSafeEqual()` over fixed-length buffers. | Never; standard `===` or `==` string equality leaks timing information. |
| Which password hashing algorithm to use? | Argon2id (memory-hard, resistant to GPU attacks). | Legacy environment with strict FIPS compliance requiring bcrypt (work factor >= 12) or PBKDF2. |
| How are user passwords stored? | Salted hash generated by algorithm; raw password wiped from memory. | Never store plain or reversibly encrypted passwords. |

---

## 3. Rules

### Constant-Time Secret Comparison (Applying Rule BE-17)
Secret comparisons (API keys, webhook signatures, tokens, password hashes) must be performed in constant time using cryptographic comparison functions (such as `crypto.timingSafeEqual` in Node.js), adhering to rule `BE-17`. Standard short-circuiting equality operators (`===` or string comparisons) are strictly forbidden for secrets.
- **Why:** Standard string equality operators return `false` on the first non-matching byte, allowing attackers to measure microscopic response time differences to iteratively reconstruct valid signatures and keys character by character.
- **Enforced by:** Linter rule and security review.

---

## 4. Constant-Time Comparison Helper

```typescript
import { timingSafeEqual, createHash } from 'node:crypto';

export const safeSecretCompare = (a: string, b: string): boolean => {
  // Hash both inputs to fixed length buffers before comparison to prevent length disclosure timing leaks
  const hashA = createHash('sha256').update(a).digest();
  const hashB = createHash('sha256').update(b).digest();
  return timingSafeEqual(hashA, hashB);
};
```

---

## 5. Failure examples
- **Failure:** Comparing incoming API token directly: `if (req.headers['x-api-key'] === process.env.API_KEY) { ... }`.
  - *Symptom:* Timing attack enables remote adversary to brute-force a 32-character API key in hours by analyzing millisecond latency variances.
- **Failure:** Hashing passwords with MD5 or plain SHA-256 without memory-hard salt.
  - *Symptom:* Database breach allows attackers to crack 80% of passwords in seconds using rainbow tables and GPU rigs.

---

## 6. Checklist for review
- [ ] Passwords hashed with `argon2id` or `bcrypt` (cost >= 12).
- [ ] API keys and tokens compared using constant-time comparison.
- [ ] Cryptographic salts are generated using a cryptographically secure pseudo-random number generator (`crypto.randomBytes`).

---

## 7. How to prove it
- **Unit Boundary:** Verify that `safeSecretCompare` returns `true` for matching secrets, `false` for non-matching, and does not crash on unequal string lengths.
