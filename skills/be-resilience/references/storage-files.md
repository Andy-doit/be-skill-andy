# Search, Files & Object Storage (S3 / MinIO)

## 1. When to read this
Read this when implementing file uploads, attachments, generating signed download/upload URLs, or interacting with AWS S3, Google Cloud Storage, or MinIO.

---

## 2. Decision table

| Question | Smallest mechanism that holds the invariant | Take more complex mechanism only when |
|---|---|---|
| How should clients upload large files? | Direct upload to object storage using pre-signed PUT URLs generated by the backend. | Files are tiny (< 100KB) and require immediate inline database processing. |
| Who enforces access control on stored files? | The backend generates time-limited signed URLs after verifying user permissions (BR-4). | Truly public static assets (e.g. public company logo, open marketing images). |
| How are file sizes and MIME types validated? | Enforced both in pre-signed URL policy constraints AND verified upon completion notification. | Uploads from strictly trusted internal systems. |

---

## 3. Rules

### Object Storage Mediated by Backend Authority (Applying BR-4 and BE-16)
Private files stored in object storage (S3, MinIO) must never be publicly exposed with public read buckets. All file downloads must use short-lived pre-signed URLs generated after verifying the caller's authorization (rule `BR-4`). Upload URLs must enforce maximum content length and content type in policy constraints (rule `BE-16`).
- **Why:** Public S3 buckets leak confidential user documents, contracts, and medical records to search crawlers. Uploading through application server memory exhausts backend RAM and connection threads.
- **Enforced by:** Integration tests verifying that unsigned URLs return HTTP 403.

---

## 4. Failure examples
- **Failure:** Creating an S3 bucket with `public-read` permission so "images are easy to display in the frontend".
  - *Symptom:* Security incident: confidential user KYC documents indexed by search engines.
- **Failure:** Uploading a 500MB video file directly through the Node.js Express server to disk.
  - *Symptom:* Server crashes with Out of Memory (OOM) as concurrent uploads saturate heap.

---

## 5. Checklist for review
- [ ] Direct file upload via pre-signed URL (`s3.getSignedUrlPromise('putObject', ...)`).
- [ ] Signed URL expiration is short (max 15 minutes).
- [ ] Policy limits file size (e.g. `['content-length-range', 0, 10485760]` for 10MB).
- [ ] S3 bucket has public access blocked (`BlockPublicAcls`, `BlockPublicPolicy`).

---

## 6. How to prove it
- **Access Control Test:** Attempt to access S3 object URL directly without signature query params; assert HTTP 403 Access Denied.
